## Summary

Implements the owner decision of 2026-11-03 on test rules (planning graph: `task-test-rules-core-20261103`, governed by `dec-orchestrate-test-assertions-and-volume-20261103`).

- `scripts/check_test_ratio.py` (standard library only, `--base`, default `origin/main`): every test file changed against the base must, as a whole, be at most 1.5x the lines of what it covers. Coverage comes from a name match or a `# covers:` / `// covers:` header. Exit status is 0 within the limit, 1 for a violation, 2 when git fails.
- New CI job `Test volume (per-file limit)`, on pull requests only. It is not a required check.
- `CLAUDE.md` Testing and `/review-loop`: the per-file limit, and tests assert behaviour rather than message wording, log text or substrings of serialized data.

Guarantees:
- G1: a changed test file over 1.5x its covered lines fails, at or under passes; whole-file lines count.
- G2: unchanged and deleted test files are never reported.
- G3: a test file with no name match and no header fails, and so does a header naming a missing file.
- G4: a covers header sums its modules and takes precedence over a name match.
- G5: a base ref git cannot resolve exits 2, not 0.

**Security impact:** none.

## What was not changed (scope)

- No existing test is trimmed and no covers headers are added in bulk; the check only reports files a PR changes.
- The about-2x PR-level norm stays as it is.
- Assertion wording is a reviewer rule; the script does not detect it.
- Name matching looks one directory above `tests/` for Python and beside the test for JS, so a file such as `X.mobile.test.jsx` needs a header.
