## 2024-05-19 - Fast edge retrieval in NetworkX MultiDiGraph
**Learning:** In `backend/core/storage.py`, `get_incident_edges` was iterating over individual nodes and calling `self.graph.out_edges(node)` and `self.graph.in_edges(node)` inside a Python loop. NetworkX supports passing an iterable of valid nodes directly to these methods (`out_edges(nodes)` and `in_edges(nodes)`), pushing the iteration into C-optimized pathways and significantly speeding up bulk edge retrieval (by about 2-3x in benchmarks). Note that for proper deduplication in MultiDiGraphs with potential self-loops or overlapping edges when querying multiple nodes, it is essential to keep the collection as a dictionary keyed by edge ID or use a `set`. Also, remember memory directive: "always call out_edges first followed by in_edges to maintain the typical iteration order expected by the test suite, and use a set to deduplicate keys caused by self-loops".
**Action:** When retrieving incident edges for a list of nodes using NetworkX, first filter to valid nodes (`[n for n in node_ids if n in graph]`), then pass that list directly to `out_edges()` and `in_edges()` instead of looping over the nodes in Python.
