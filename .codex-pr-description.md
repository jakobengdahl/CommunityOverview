## Summary

Record node additions and removals in session activity. Additive visualization
pushes now persist membership for stored shared sessions before broadcasting,
including when no browser is connected. Browser echoes cannot duplicate the
record or replace its MCP/auto-add attribution. The existing activity view shows
localized counts and automated actor labels.

## Design

The server records exactly one entry for each applied membership change; an
idempotent echo records nothing. Membership records share the activity list but
have an independent 500-record cap and the same seven-day age limit, preserving
the separate 500-record budget for other activity. Each membership record holds
a total count and at most MAX_ACTIVITY_NODE_IDS (100) IDs, once, with no
before/after snapshots, forward operation or inverse. User actions retain their
presence identity. MCP writes display “via MCP”; deterministic auto-add writes
display “Auto-add agent”. The shared MCP client ID cannot identify individual
MCP callers. Membership does not invalidate redo history.

## What was not changed (scope)

Legacy-only visualization channels still require a browser to apply commands.
Membership removal remains non-undoable because it also changes group membership
and other canvas state. Delivery reports continue to describe live consumers,
independently of persisted membership. No schema or dependency changes.
Network-dependent planning graph updates, PR publication, CI and live-service
checks were skipped as requested. No owner decision was needed.
