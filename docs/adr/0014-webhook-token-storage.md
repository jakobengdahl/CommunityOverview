# 0014. Webhook token storage

Webhook credentials are generated by the application and returned only when
minted or rotated. A dedicated SQLite database, `webhook_tokens.db`, lives
in `COMMUNITYOVERVIEW_PRIVATE_STATE_DIR` (default `~/.local/state/communityoverview`), separate from the graph and import jobs databases. It stores SHA-256 hashes and token
metadata, never plaintext credentials. Graph export and import do not include
this database. Operators must protect and back up private state separately.

One active token is allowed per function. Rotation replaces its hash in a
single transaction; revocation deletes the row. Management requires an `admin`
authorization decision for the bound graph. The default hook denies this action;
hosts must provide a hook that grants graph administration explicitly. This
storage does not enable webhook invocation.

Minting requires a valid installed function and an explicit operator-owned mapping
from function ID to graph ID in the JSON object environment variable
`COMMUNITYOVERVIEW_FUNCTIONS_WEBHOOK_GRAPHS`. An absent or mismatched binding
does not permit minting.
